# SPC-0001 · Core catalog discovery, stream resolution, and adaptive playback skeleton

Tier: **skeleton** · Readiness: **100%**

The walking skeleton of Lumen: zero-configuration browsing and search across Movies, Series, and Anime catalogs, multi-provider stream discovery with streamability ranking, peer-to-peer head/tail piece prioritization, three-tier adaptive media playback (direct byte-range play, lossless video remux, and full on-the-fly transcoding with seek support), and automatic source failover on stall.

## Non-goals

- Do not require user accounts, cloud authentication, or external media library servers to browse or play content.
- Do not persist downloaded media files permanently outside the bounded ephemeral playback cache.

## Requirements

### REQ-0001 · Keyless multi-catalog browsing, cross-catalog search, and anime identifier resolution (active)

The system MUST provide zero-configuration browsing and search across Movies, Series, and Anime catalogs without requiring user accounts or mandatory API keys, surfacing only real catalog titles on the Home view without static open-movie placeholder rows.
- **Movies & Series catalogs**: Support trending, popular, top-rated, genre-filtered, and release-year-filtered views, plus full title details with IMDb identifiers, cast, runtime, ratings, and season/episode lists.
- **Anime catalogs**: Support trending, current-season, popular, and top-rated views, and automatically cross-reference each seasonal anime entry (`anilist:<id>`) against the community anime mapping dataset (refreshed every `24 hours` with fallback mirror support) to resolve its `kitsuId` (for episode stream queries) and `imdbId` + `season` number (for subtitle queries).
- **Unified search**: Query Movie, Series, and Anime catalogs concurrently for any search query of at least `2` characters.

**REQ-0001#1**

```gherkin
Given a fresh deployment with no environment variables or API keys configured
When a user browses the Home, Movies, Series, or Anime views or searches for a title
Then the system returns populated catalog items with posters, ratings, genres, and episode lists, with no static open-movie placeholder rows injected on the Home view
```

**REQ-0001#2**

```gherkin
Given an anime entry selected from the Anime catalog (`anilist:<id>`)
When the user opens a specific episode for playback
Then the system resolves the corresponding Kitsu identifier for stream discovery and the IMDb identifier + season number for subtitle lookup
```

Because:
- FCT-0001 (active): Public keyless catalogs provide movie, series, anime, and air-date metadata without user accounts
- FCT-0002 (active): Anime catalogs index by seasonal entry IDs while stream and subtitle providers index by canonical Kitsu or IMDb IDs

### REQ-0002 · Multi-provider stream discovery and deterministic streamability ranking (active)

The system MUST query configured stream addons and indexers in parallel, normalize magnet URIs, info-hashes, file indices, quality labels, seed counts, and file sizes, and rank candidate streams by a deterministic **streamability score** before selecting a default source:
- **Direct HTTP / debrid streams**: `+1000` over peer-to-peer torrents.
- **Resolution preference**: `1080p` (`+300`), `720p` (`+260`), `480p` (`+120`), `Auto` (`+100`), `4K` (`+40`).
- **Codec & format adjustments**: `H.264`/`AVC` (`+40`), `MP4`/`WEB-DL`/`WEBRip` (`+30`), `HEVC`/`x265` (`-250`), `HDR`/`Dolby Vision` (`-150`), `Remux`/`BDRemux` (`-200`), `CAM`/`TS` (`-300`).
- **Swarm health (torrents)**: `0` seeds receives `-400`; positive seed count adds `min(250, log2(seeds + 1) * 45)`.
- **File size bounds**: `>15 GB` (`-250`), `>6 GB` (`-100`), `<0.3 GB` (`-80`).

**REQ-0002#1**

```gherkin
Given candidate streams for a title that include a 4K HEVC remux with 5 seeds, a 0-seed 1080p torrent, and a 1080p H.264 WEB-DL torrent with 80 seeds
When the system ranks the available sources
Then the 1080p H.264 WEB-DL source with 80 seeds is ranked first and selected by default
```

Because:
- FCT-0003 (active): Standard playback clients decode only a subset of video and audio codecs natively
- FCT-0005 (active): Peer-to-peer stream candidates vary widely in active seeders, bitrate, and codec compatibility

### REQ-0003 · Peer-to-peer head-and-tail piece prioritization, byte-range streaming, and idle swarm eviction (active)

When streaming from a peer-to-peer swarm, the system MUST:
1. Augment magnet URIs with a daily-refreshed list of live public tracker announce URLs alongside built-in fallback trackers.
2. Select the target video file (by explicit `fileIdx`, exact season/episode pattern match `SxxExx` / `1x02` / anime episode number, or largest video file fallback).
3. Immediately prioritize piece ranges covering the **head** (`2%` of file size, clamped between `16 MB` and `64 MB`) and the **tail** (final `4 MB` of the file) with high priority, deselecting non-essential pieces until initial buffering succeeds.
4. Expose real-time buffer and swarm telemetry (`state`, `headBytes`, `headTarget`, `tailReady`, `aheadBytes`, `peers`, `downloadSpeed`, `progress`, `complete`, and normalized `[startRatio, endRatio]` `downloadedRanges` for verified on-disk piece intervals) and serve the selected file over HTTP byte-range (`206 Partial Content`) responses.
5. Automatically tear down and remove torrent engines and temporary cache files after `20 minutes` of inactivity or explicit session release.

**REQ-0003#1**

```gherkin
Given a magnet link for a 2 GB media file whose container index resides in the final 4 MB
When the stream prepare endpoint is polled prior to playback
Then the engine prioritizes the leading 40 MB (2%) and trailing 4 MB piece ranges, exposes coalesced normalized `downloadedRanges` for verified piece intervals, and reports `ready` once either the head+tail targets or 1.5x the head target are contiguous on disk
```

**REQ-0003#2**

```gherkin
Given an active torrent swarm that has received no read or status requests for 20 minutes
When the periodic cleanup sweep runs
Then the swarm engine is destroyed and its temporary cache files are removed from disk
```

Because:
- FCT-0004 (active): Media containers store stream and seek index tables at either the start or the final megabytes of the file
- FCT-0011 (active): Multi-layer timeline buffer visualization and hover seek-readiness feedback eliminate peer-to-peer seek ambiguity

### REQ-0004 · Pre-playback stream inspection and three-tier adaptive media pipeline (active)

Before starting playback, the system MUST inspect the media input to determine container format, duration, video codec, audio tracks (preferring English `eng`/`en`, then default disposition, then first track), and embedded text subtitle streams, and route playback through one of three tiers:
1. **Tier 1 — Direct Play**: When the container is `mp4` or `webm` (excluding `.mkv`/`.avi`), the video codec is in `{h264, vp8, vp9, av1}`, and the preferred audio codec is in `{aac, mp3, opus, vorbis, flac}` as the first audio track, serve the raw byte stream directly via HTTP `206 Partial Content`.
2. **Tier 2 — Lossless Video Remux**: When the video codec is already client-compatible (`{h264, vp8, vp9, av1}`) but the container (e.g., `mkv`) or audio track (`ac3`, `eac3`, `dts`, or non-first audio track) is incompatible, copy the video bitstream without re-encoding and transcode only audio to stereo `AAC` (`192 kbps`) inside a fragmented MP4 (`fMP4`) stream.
3. **Tier 3 — Full On-the-Fly Transcode**: When the video codec is incompatible (`hevc`/`h265`, etc.), transcode video to `H.264` (downscaling only if height `> 1080p`, with optional GPU hardware acceleration and automatic fallback to low-latency software encoding at `CRF 23`) and audio to stereo `AAC` inside a fragmented MP4 (`fMP4`) stream, supporting arbitrary time-offset seeking (`start` seconds) via timeline offset adjustment.

**REQ-0004#1**

```gherkin
Given an MKV media stream containing 1080p H.264 video and 5.1 EAC3 audio
When the client probes the stream and starts playback
Then the system reports `directPlayable: false, copyVideo: true, copyAudio: false` and streams a fragmented MP4 with copied H.264 video and transcoded stereo AAC audio
```

**REQ-0004#2**

```gherkin
Given a transcoded or remuxed stream where the viewer seeks to 00:45:00 (`start=2700`)
When the client requests the transcode stream at `start=2700`
Then the server restarts the media pipeline at the `2700`-second offset and the player timeline maps seek positions relative to `2700` seconds
```

Because:
- FCT-0003 (active): Standard playback clients decode only a subset of video and audio codecs natively
- FCT-0004 (active): Media containers store stream and seek index tables at either the start or the final megabytes of the file

### REQ-0005 · Automatic source failover, multi-layer timeline buffer visualization, and keyboard playback controls (active)

The player MUST automatically fail over to the next highest-ranked stream candidate when a source fails to initialize, returns a fatal playback error, or stalls for `25 seconds` before the first frame is rendered, MUST render a multi-layer timeline scrubber with seek-readiness feedback, and MUST support full keyboard navigation:
- **Multi-layer timeline scrubber**: Render four distinct visual layers on the playback timeline—unloaded track, subtle sky-tinted verified on-disk swarm piece ranges (`downloadedRanges`, transitioning to an emerald tint with a `100% Downloaded` badge when `complete` is true), brighter white in-memory decoded browser buffer ranges (`HTMLMediaElement.buffered`), and rose-to-orange played progress with an interactive playhead thumb.
- **Hover seek-readiness preview & legend**: Hovering the timeline displays the target timestamp alongside its seek readiness (`Instant seek · Buffered in memory`, `Fast seek · Downloaded on disk`, or `Will buffer from peers`), and clicking the stream status pill opens a legend explaining each timeline layer and live swarm telemetry.
- **Keyboard shortcuts**:
  - `/` focuses the global search input when the player is closed.
  - `Space` or `K` toggles play/pause; `Left` / `Right` seeks `-10s` / `+10s`.
  - `Up` / `Down` switches to the previous/next channel during Live TV playback.
  - `F` toggles fullscreen, `P` toggles Picture-in-Picture, `M` toggles mute, `C` toggles subtitles, `G` / `H` shifts subtitle timing by `-0.5s` / `+0.5s`, and `Esc` closes open menus or exits the player.

**REQ-0005#1**

```gherkin
Given a movie with 3 ranked stream sources where Source #1 stalls with 0 bytes or fails during initial buffering
When 25 seconds elapse without playback readiness or an error occurs
Then the player automatically releases Source #1 and switches to Source #2 without user intervention
```

**REQ-0005#2**

```gherkin
Given an active peer-to-peer playback session with partially or fully downloaded piece ranges
When the viewer inspects or hovers the playback timeline scrubber
Then the timeline renders separate layers for played progress, in-memory decoded buffer, and on-disk downloaded piece ranges, and displays the hovered timestamp's seek-readiness status
```

Because:
- FCT-0005 (active): Peer-to-peer stream candidates vary widely in active seeders, bitrate, and codec compatibility
- FCT-0011 (active): Multi-layer timeline buffer visualization and hover seek-readiness feedback eliminate peer-to-peer seek ambiguity

## Current Production Appliance Stack

Lumen compiles and ships as a single self-contained binary with the frontend bundle embedded directly into the executable (`//go:embed`).

| Layer | Technology | Role |
| :--- | :--- | :--- |
| **Backend & HTTP Appliance** | **Go 1.24+** (`net/http`, `cmd/lumen`, `internal/server`) | Single-binary HTTP server, API router, static SPA asset server (`io/fs`), and SSRF-guarded outbound proxy. |
| **Frontend SPA** | **Vite 8** + **React 19** + **TypeScript 5** (`src/`) | Client-side single-page application compiled to `web/dist` and embedded into the Go binary via `web/embed.go`. |
| **Styling & Icons** | **Tailwind CSS 4** + **Lucide React** | Dark-mode glassmorphic UI, viewport-aware custom dropdowns, 4-layer playback timeline scrubber, and responsive layout. |
| **App Design Tokens** | **ASDLC Meta-DesignSystem** (`asdlc-meta-designsystem@latest`) | `tokens.css` imported in a low-priority layer by `src/app/globals.css`, with fallbacks; used by the page canvas and the player controls. |
| **Specification Workspace UI** | **ASDLC Meta-DesignSystem** (`asdlc-meta-designsystem@latest`) | Zero-build Web Component Atoms, Molecules, Organisms, and Templates powering `site/`. |
| **BitTorrent Streaming Engine** | **`github.com/anacrolix/torrent`** (`internal/streaming`) | Real-time torrent swarm ingestion, custom piece prioritization (head/tail + dynamic readhead window), contiguous downloaded-range calculation, and 20-minute idle eviction. |
| **Media Remuxing & Transcoding** | **`ffmpeg` / `ffprobe`** (`internal/streaming`) | Runtime codec probing (`h264`, `hevc`, `aac`, `ac3`, `eac3`), zero-CPU fragmented MP4 (`fMP4`) copy-remuxing, and on-the-fly audio/video transcoding with `-ss` seek support. |
| **Live TV HLS Playback** | **`hls.js` 1.7** + Native `<video>` (`src/components/VideoPlayerModal.tsx`, `internal/live`) | Adaptive HLS live stream playback paired with `/api/live/proxy` manifest rewriting and CORS relay. |
| **Household State Persistence** | **`modernc.org/sqlite`** (`internal/state`) | Pure-Go (CGO-free) embedded SQLite database (`WAL` mode) storing isolated per-member household profiles (`name`, `nickname`, `color`, `is_kids`), watch progress, per-episode resume positions, and favorite live channels. |
| **Network Security Guard** | **`net.Dialer.Control`** (`internal/netguard`) | Socket-level IP validation at connection time to block RFC1918, loopback, link-local, CGNAT, and cloud metadata addresses and eliminate DNS-rebinding TOCTOU windows. |

## Directory Layout

- `cmd/lumen/main.go` — Single-binary entrypoint (`PORT`, `LUMEN_DATA_DIR`).
- `internal/server/` — HTTP handlers for `/api/health`, `/api/media/*` (including `?kids=1` filtering in `kids.go`), `/api/stream`, `/api/stream/status`, `/api/subtitles/*`, `/api/live/*`, and `/api/state`.
- `internal/metadata/` — Keyless Cinemeta, AniList GraphQL, `Fribb/anime-lists` cross-reference, and optional TMDB client with genre ID mapping.
- `internal/scrapers/` — Concurrent Torrentio, TPB (`apibay.org`), YTS, Nyaa/AnimeTosho, and custom Stremio addon scrapers with source ranking.
- `internal/streaming/` — `anacrolix/torrent` engine, piece prioritization, `downloadedRanges` telemetry, and `ffmpeg`/`ffprobe` remux/transcode pipeline.
- `internal/live/` — Free-TV/IPTV M3U parser with ISO country attribution & `Kids` classification, fallback broadcaster list, and HLS manifest/segment CORS proxy.
- `internal/subtitles/` — OpenSubtitles REST v3 lookup and SRT-to-WebVTT converter.
- `internal/state/` — Embedded SQLite per-member household state store (`profile_watch_progress`, `profile_favorite_channels`, `household_profiles`).
- `internal/personalization/` — Genre affinity scoring and row personalization.
- `internal/netguard/` — SSRF and DNS-rebinding socket-level dialer guard.
- `src/` — React 19 + TypeScript SPA source (`Navbar`, `HeroBanner`, `MediaCarousel`, `PosterCard`, `CatalogBrowser`, `MediaDetailModal`, `LiveChannelsGrid`, `VideoPlayerModal`, `SettingsModal`, `ProfileManagerModal`, `SelectDropdown`, `kidsFilter.ts`, `watchProgress.ts`).
- `web/` — `//go:embed all:dist` package embedding the production Vite bundle.
